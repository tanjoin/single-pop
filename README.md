# single-pop

ブックマークレットから中継ページを呼び出し、遷移先を名前付きのポップアップで管理します。

## 使い方

1. `index.html` をGitHub PagesなどのHTTPS、またはlocalhostに配置して開き、遷移先の http(s) URL を入力します。
2. 「Single Popup」をブックマークバーにドラッグして登録します。
3. 任意のページでブックマークレットを実行します。
4. 自動起動がブロックされた場合や前面に出ない場合は、管理中の中継ページの「最前面に表示 / 起動」を押します。

URLは中継ページの入力欄で変更できます。入力値はブラウザーに保存されます。登録済みブックマークレットには登録時のURLが含まれるため、変更後は登録し直してください。

## 動作

- 通常表示、リロード、履歴からの復帰では遷移先を開きません。
- ブックマークレットの起動要求は処理前にURLから取り除き、一度だけ処理します。
- 開いた遷移先の参照が有効な間は、同じURLへの要求では再読み込みせずフォーカスだけを要求します。異なるURLへの要求は同じウィンドウで遷移させます。
- 遷移先が閉じられている場合は、同じウィンドウ名で開き直します。
- 管理担当の中継ページを閉じると、管理している遷移先ポップアップも閉じます。戻る操作で中継ページがBFCacheに入る場合は閉じません。
- HTTPSまたはlocalhostなど、Web LocksとBroadcastChannelが使える環境では、同一オリジンの中継ページのうち1つだけが遷移先を管理します。別タブからの呼び出しで重複した中継ページが開いても、要求を管理担当へ転送し、受領確認後に重複ページ自身を閉じます。起動要求がない重複ページも、管理担当の表示を要求してから閉じます。受領前に担当が閉じられた場合は、待機中のページが未処理の要求を引き継ぎます。
- ブックマークレットからの呼び出しはユーザー操作中に同期実行し、中継ページを開く際のポップアップブロックを避けやすくしています。

## ブラウザーの制限

「常に1つで最前面」はWebページだけでは保証できません。この実装は、ウィンドウ参照の再利用、名前付きウィンドウ、管理担当の排他制御と、手動ボタンによるフォーカス要求を組み合わせたベストエフォートです。OSの「常に手前に表示」を設定するものではありません。

- 中継ページの自動起動や `focus()` はブラウザーに拒否される場合があります。中継ページにポップアップを許可し、管理中のページのボタンを押してください。別の中継ページからの転送にはユーザー操作の権限は引き継がれません。
- ブラウザーがスクリプトによる閉鎖を許可しない重複ページは自動で閉じられません。その場合は遷移先を前面にした後に案内を表示するので、その重複タブを手動で閉じてください。
- 中継ページのリロードでJavaScriptのウィンドウ参照は失われます。次の起動操作では同じ名前で再取得を試みるため、遷移先が再読み込みされる場合があります。
- 遷移先が `Cross-Origin-Opener-Policy` などでウィンドウを分離した場合や、ブラウザーがウィンドウ名の再利用を制限した場合は、重複を防げないことがあります。完全な保証が必要な場合は、タブ・ウィンドウを管理できるブラウザー拡張が必要です。
- `file://` でも設定画面は開けますが、外部サイトのブックマークレットからローカルファイルを開く操作は拒否される場合があります。ファイルのオリジン、保存、ページ間通信の扱いもブラウザー依存です。実運用には、同じHTTPS URLまたはlocalhostで中継ページを使ってください。Web Locks非対応環境では、名前付きウィンドウによる再利用のみになります。
- ブラウザープロファイル、プライベートウィンドウ、異なる中継ページのオリジンをまたぐ管理はできません。CSPなどによりブックマークレット自体が実行できないページもあります。

## localhostで使う

Node.jsとnpmがインストールされている環境で、次の手順を実行します。アプリのビルドは不要です。

1. ターミナルで、このリポジトリーのディレクトリーへ移動します。
2. 次のコマンドで静的ファイルサーバーを起動します。初回はnpmから `http-server` を取得するため、インターネット接続が必要です。

	```sh
	npx --yes http-server . -a 127.0.0.1 -p 8080 -c-1
	```

3. ブラウザーで <http://localhost:8080/index.html> を開きます。ファイルを直接開くのではなく、このURLを使ってください。
4. 遷移先の http(s) URL を入力し、「Single Popup」をブックマークバーにドラッグして登録します。以前 `file://` や別のURLで生成したブックマークレットは登録し直してください。
5. `http://localhost:8080` のポップアップをブラウザーのサイト設定で許可します。
6. 別のWebページでブックマークレットを実行します。前面に出ない場合は、管理中の中継ページの「最前面に表示 / 起動」を押します。

localhostはHTTPでもセキュアコンテキストとして扱われるため、対応ブラウザーではWeb LocksとBroadcastChannelを利用できます。遷移先自体をlocalhostに置く必要はありません。

- 使用中はサーバーを起動したままにしてください。停止はターミナルで `Ctrl+C`、再開は同じディレクトリーで同じコマンドを実行します。
- `localhost` と `127.0.0.1`、または異なるポート番号は別オリジンです。中継ページは常に `http://localhost:8080/index.html` に統一してください。
- 8080番ポートが使用中なら、コマンドの `-p 8080` とブラウザーで開くURLを同じ別ポートへ変更します。変更後はブックマークレットも登録し直してください。
- 起動コマンドはループバックアドレスにのみ公開します。同じネットワークの別端末からアクセスするための設定ではありません。

## テスト

Node.jsの標準テストランナーで実行できます。追加依存はありません。

```sh
node --test tests/single-pop.test.cjs
```
